### L-20260930-1: Предотвращение дублирования публикаций в Telegram при асинхронной отправке
- Триггер: отправка сообщений/анонсов через Telegram Web CDP / UI автоматизацию
- Было: после первого клика по отправке скрипт сразу проверил DOM; из-за задержки рендера нового бабла решил, что сообщение не ушло, и кликнул повторно, создав дубликат в теме
- Причина: Telegram Web K обновляет DOM баблов с небольшой асинхронной задержкой (до 1-2 сек). Быстрая проверка DOM сразу после клика даёт ложноотрицательный результат
- Стало: после отправки ждать очистки поля ввода (`inputText === ''`) и появления нового бабла с таймаутом до 3-5 секунд; ни при каких условиях не слать повторный клик вслепую без проверки `isOut` баблов по `mid` или тексту в истории
- Проверка: убедиться, что в чате присутствует ровно один бабл с текстом анонса (`bubbles.filter(b => b.hasTarget).length === 1`)
